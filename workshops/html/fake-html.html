Document Parsing Workshop

This sample covers the most common HTML elements you will encounter when building a RAG pipeline. The goal is to extract clean text while preserving structure such as headings, lists, and tables.

1. Why Clean HTML First

Raw web pages often contain navigation bars, cookie banners, scripts, and footer links. Before chunking, you should remove boilerplate and keep only the main content. A good parser distinguishes between narrative paragraphs and metadata like dates or author names.

  • Remove headers and footers
  • Extract titles and body paragraphs
  • Preserve table row and column relationships
    • Nested lists should stay in reading order
    • Sub-items often carry important detail
  • Skip empty elements and duplicate whitespace

2. Supported Block Types

The table below maps HTML tags to the block types used in our parser output schema.

HTML Tag Block Type Notes
h1 – h6 title Use font size or tag level to infer hierarchy
p paragraph Merge hyphenated line breaks when needed
table table Flatten cells left-to-right, top-to-bottom
ul / ol list Keep bullet or number prefix for context
a link Prefer link text over raw URL when both exist

2.1 Inline Formatting

Inline tags such as bold, italic, and internal links should be stripped or normalized to plain text depending on your downstream model. Most embedding models work best with unformatted strings.

3. Chunking Guidelines

  1. Split on heading boundaries when possible
  2. Keep tables as single chunks if they fit the token limit
  3. Attach section titles as metadata rather than repeating them in every chunk
  4. Record parse warnings when structure looks ambiguous

When in doubt, print the element list from your partitioner and inspect ordering before sending chunks to the vector store. Small mistakes in reading order are hard to fix after indexing.
